# PM mode

在 pi 中讨论、review，以及按用户明确要求复现、测试和预览；仅在用户明确要求时通过 Multica 记录需求与 BUG、分配负责人，由负责人实施、验证和跟进。当前协调会话不自动接手代码实施或持续巡视。PR review 和已授权的 Git 提交、合并、推送可在当前会话完成，不强制创建/更新 Issue 或分派 Agent；结果直接回复聊天，另有记录要求时除外。模式默认关闭，不禁用修改工具；执行边界通过工作流约定管理，不是安全沙箱。

## 使用

本扩展位于个人扩展目录，无须新增依赖或修改 `settings.json`。在 pi 中执行 `/reload`，然后：

```text
/pm                                 进入，无绑定时匹配项目；歧义时选择
/pm off                        关闭，保留本会话的项目绑定
/pm project                    重新选择 workspace / project
/pm project <workspace-id> <project-id>   用已明确的 ID 选择
/pm status                     刷新任务快照
/pm issue CERE-54               聚焦 issue，读取正文、评论摘要与活动 Run
/pm issue                      清除聚焦
```

也可启动时传入 `--pm`；无绑定且用户要求项目操作时让模型调用 `multica_select_project` 发现候选并请用户确认。非交互接口不能确认歧义目标，不会自行绑定。需要不同的人类 CLI profile 时使用 `--multica-profile <name>`；托管任务不得通过该参数切换人类凭据。

工具：

- `multica_select_project`：发现候选，传入两项 ID 后通过确认对话框切换项目。
- `multica_overview`：读取当前项目任务；可设置/清除聚焦 issue 和真实的 `waitingFor` 待确认事项。

## 行为

- 每轮设置 `agent/skills/pm-mode/SKILL.md` 的轻量规则与缓存绑定/聚焦/待确认数据，不注入任务快照或错误正文。只有用户明确要求 issue 操作时才加载 `issue-workflow` 入口及对应 references：创建、跟进、分派/执行分别走对应路由。遇到影响范围、归属、执行或安全的不确定性，先询问用户。
- Review 不授权修复、合并或推送，合并也不额外授权请求范围外的推送。清晰授权直接执行，不重复询问；先核验仓库、PR、head/base、分支和远端，检查暂存/未暂存改动并保留无关修改。目标或安全有实质歧义时才澄清；强推、破坏性重置仍需对应授权。PM 模式本身不构成授权，Git／PR 协作不触发 Multica 查询。
- 当前目录与**本机 daemon** 的目录资源匹配优先于仓库匹配；路径使用真实路径和目录边界，最长匹配优先。同等级多个候选需要选择，不跨机器猜测本地路径。
- 状态保存到 pi 会话的当前分支，不写项目配置。恢复时仅在本地检查目录/profile/service，不读取平台状态，不自动启动工作。
- 普通对话、连续轮次、会话恢复及已有绑定时重新开启模式均不自动读取平台。首次选择项目只发现并核验项目，不读取任务。仅用户要求查看、手动 `/pm status` / `/pm issue`、项目定位、查找已有任务及授权任务操作前后的必要核验会读取；缓存始终标记为历史快照。
- 常驻界面仅保留单行 `PM mode · 项目` 状态，不显示任务 widget。通过 `/pm status`、工具或 Multica 看板按需查看任务详情；内部快照、聚焦与待确认事项继续保留，读取失败会清除旧快照。
- 任务概览最多返回最新 100 个任务，明确标记更多数据。评论仅为顶层摘要；判断重复、执行或验收前仍需搜索、分页并展开相关线程。
- 扩展本身仅远程读取。模型根据用户授权，通过 Multica CLI 创建/更新/分派任务；模式不会用 shell 字符串匹配冒充完整的权限控制。分派与启动分开授权：仅分派使用 CLI 支持的 `assign/update --no-start`（`create` 不支持此参数，新任务先无负责人创建，再 `assign --no-start`）；代码实施需要负责人处理时默认回复或更新 Issue，说明问题、改动要求和下一步；一般“执行”“修复”“写入 Skill”不授权直接启动 Run。只有明确要求直接启动或重启 Run 才调用 rerun 等操作；回复/更新可能已触发执行，不叠加 rerun、提及或状态变更重复启动。不确定时先询问并等待，不把 review、测试或预览当作修复授权。关键写入、执行及新标签创建遵循确认规则。
- 人类交互控制会话的 CLI 读取使用系统临时目录作为工作目录，以免与同项目 Agent Run 的 `.multica` 标记冲突；不删除标记、不读取任务令牌。git 仓库匹配仍在项目目录执行。托管任务保持任务目录和注入的凭据。

## 边界

Multica CLI 需要已登录。支持已核验的 CLI 0.6.1 读取接口；接口变化时应先更新帮助和验证。网络或 daemon 不可达时不猜测目标、不自动登录或启动 daemon。CLI 出现 TLS 握手超时，应按 CLI 提示由用户配置网络兼容选项。

看板仍使用 Multica。无后台轮询，pi 退出后不会继续监控或唤醒；执行中的 Agent 仍由 Multica 管理。模式不提供文件系统隔离，不擅自 commit/merge/push，不把 Run 完成当作用户验收。涉及里程碑时先核验平台支持，不伪造能力。
