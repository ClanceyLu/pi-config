# 全局开发规则

## 修改前同步最新代码

- 在 Git 仓库中开始修改前，先核验仓库、当前分支、远端及其跟踪分支，检查暂存、未暂存、未追踪文件和未完成的合并；不能猜测远端或目标分支。
- 工作区干净、跟踪目标明确且没有未完成的合并时，执行 `git pull --ff-only`，成功同步后再修改。新任务的分支/worktree 从已核验的最新远端主分支提交创建，并记录基准 SHA。
- 存在未提交改动、分支分叉、冲突或远端不可达时，保留现有工作并报告阻塞，取得明确处理决定后再继续；不得为同步而自动 stash、丢弃改动、rebase、强制重置或强推。不得静默跳过同步并声称代码已是最新。
- 同步授权仅用于读取远端及快进当前已核验的跟踪分支，不包含推送、部署或扩大任务范围；用户明确要求离线或保持指定版本时遵循该要求，并说明未同步的状态。非 Git 目录不执行拉取。

## UI 文案与用户提示词隔离

- 用户提示词中的实现要求、验收标准、限制条件和解释性描述，默认只用于指导实现，不得直接或改写后作为面向最终用户的 UI 文案。
- 不得为了说明已遵循要求，而在界面中添加诸如“最终结果不会自动保存”“按要求未实现某功能”“这是演示页面”等元说明。
- 只有当用户明确要求在界面展示该文案，或该信息确实是产品使用所必需的状态、警告、错误或操作说明时，才可以展示；此时应使用符合产品语境、面向最终用户的文案。
- 交付前检查本次新增或修改的所有可见 UI 文案，移除源自提示词但不属于产品需求的元信息。
